# SeerBrowserPro 需求清单

- 项目：基于 YOLO26 的 Canvas 网页游戏自动化浏览器
- 版本：v0.1.0（一期）
- 平台：Windows（Electron 桌面应用，架构上跨平台）
- 日期：2025-07

---

## 1. 项目目标

做一款内置智能识别能力的网页浏览器：在浏览器中正常打开任意网页，对基于 **Canvas** 渲染的**模拟经营类**网页游戏，能够自动探测游戏画布、用 **YOLO26** 目标检测模型识别画面中的功能元素（按钮、图标、弹窗、资源点等），把识别结果沉淀为可复用的「功能模块」缓存，并以拟人化的鼠标轨迹自动点击，最终形成"识别 → 缓存 → 执行"的闭环。

## 2. 用户角色与典型场景

| 角色 | 场景 |
|---|---|
| 游戏挂机玩家 | 打开游戏页 → 探测画布 → 识别"开始/领取/升级"等功能 → 配置循环任务 → 挂着自动收菜 |
| 数据/模型贡献者 | 在不同游戏页面截图、人工框选标注 → 导出 YOLO 数据集 → Python 训练 → 导出 ONNX 导回应用 |
| 高级用户 | 手动指定画布、调整置信度/IoU 阈值、dryRun 预演、Esc 紧急停止 |

## 3. 功能需求（对应原始 6 条需求）

### R1. Canvas 自动探测与手动配置 ★已实现

| 编号 | 需求 | 验收标准 |
|---|---|---|
| R1.1 | 自动枚举页面中全部 `<canvas>` | 探测结果列出序号、CSS 选择器、id/class、backing store 尺寸、视口矩形、可见性 |
| R1.2 | 识别画布上下文类型 | 输出 `2d / webgl / webgl2 / webgpu / unknown`；通过 CDP 注入 `getContext` 包装在页面脚本执行前记录 `data-seer-ctx`，零副作用；注入失败时加载后 `getContext` 回退探测 |
| R1.3 | 活动差分检测 | 连续两帧截图计算变化率 `activity`，识别"正在动的真游戏画布"，过滤隐藏/静态画布 |
| R1.4 | 自动推荐最佳画布 | 按面积、可见性、活跃度综合评分给出 `bestIndex` 并自动选中 |
| R1.5 | 手动配置 | 用户可按序号或 CSS 选择器切换目标画布 |
| R1.6 | 多画布页面 | 同页多个画布均可枚举，且全部 iframe 内主框架导航均能再次注入钩子 |

### R2. YOLO26 推理识别 + 模拟点击（一期仅模拟类游戏）★已实现

| 编号 | 需求 | 验收标准 |
|---|---|---|
| R2.1 | 内置 ONNX 推理引擎 | onnxruntime-node（CPU EP）加载 YOLO26 导出的 ONNX，应用内一键单次推理 |
| R2.2 | 同时支持两种模型输出头 | ① e2e 端到端头 `(1,300,6)`：模型自带 NMS，直接解码；② standard 标准头 `(1,4+nc,8400)`：应用内置置信度过滤 + 分类 NMS；头类型可自动识别也可手动指定 |
| R2.3 | 输入预处理 | letterbox 等比缩放 + 灰边填充（114）、RGB、NCHW、1/255 归一化，支持任意输入边长（默认 640） |
| R2.4 | 输出检测元素 | 每条结果含 `classId / label / confidence / 包围盒`，并换算成 bitmap、CSS、canvasNorm、viewportNorm 四套坐标 |
| R2.5 | 模拟点击 | 对选中检测结果执行点击，走 `webContents.sendInputEvent`（`isTrusted=true`，页面无法区分），含鼠标移动→按下→抬起完整序列 |
| R2.6 | 拟人化 | 点击坐标加微抖动，移动路径为贝塞尔曲线 + 多步插值 + 随机间隔，避免固定坐标机械点击 |
| R2.7 | 一期游戏类型范围 | 仅模拟经营/模拟类：识别 UI 功能元素并点击；动作类型预留 click/dblclick/rightclick/drag |
| R2.8 | 离线演示模型 | 可一键生成假 ONNX 模型（12 个固定检测框），在没有训练数据时验证全链路 |
| R2.9 | 获取官方模型 | 可一键通过 Python 拉取官方 `yolo26n.pt` 并导出 ONNX（用于链路验证/通用物体检测） |

### R3. 功能模块缓存 ★已实现

| 编号 | 需求 | 验收标准 |
|---|---|---|
| R3.1 | 页面身份识别 | 用 origin、path 模式、标题、DOM 结构哈希、视觉哈希（多尺度灰度均值）生成页面签名 |
| R3.2 | 缓存内容 | 每个缓存模块记录：标签、classId、动作类型、**相对 Canvas 的归一化包围盒**、相对视口归一化包围盒、32×32 灰度缩略图模板、置信度、命中次数、锁定标记、备注 |
| R3.3 | 跨分辨率鲁棒 | 缓存坐标全部归一化（0~1），窗口/画布尺寸变化后点击前实时还原为当前 CSS 像素 |
| R3.4 | 页面自动匹配 | 导航完成后用签名匹配已缓存页面，命中即恢复模块列表 |
| R3.5 | 模板校验 | 点击前可用缓存的缩略图模板与当前画面做相似度校验，防止 UI 改版后误点 |
| R3.6 | 模块管理 | 支持保存、编辑（动作/锁定/备注）、删除模块、删除整页；持久化到 userData 的 JSON |
| R3.7 | 检测覆盖层 | 在游戏视图上叠加半透明框 + 标签，实时显示检测/缓存结果，可一键清除 |

### R4. YOLO26 模型 ★已实现

- 使用 Ultralytics YOLO26（参考 https://docs.ultralytics.com/zh/models/yolo26 ）。
- 训练/导出完全在 Python 侧（ultralytics），应用侧只消费 **ONNX 文件**，不依赖也不调用 ultralytics。
- 推荐导出 `nms=False` 的端到端头 `(1,300,6)`，应用侧零 NMS 依赖；同时兼容标准头。
- 详细搭建步骤见 [开发清单.md](./开发清单.md) 第 4 章。

## 4. 非功能需求

| 项 | 要求 | 一期实际 |
|---|---|---|
| 性能 | 640×640 CPU 单次推理 < 200ms | 演示模型 ~6ms；官方 yolo26n CPU 预期 30~120ms（视机器） |
| 可信输入 | 模拟事件必须为 `isTrusted` | sendInputEvent，满足 |
| 稳定性 | 推理失败/模型缺失/Python 缺失均不崩溃，有错误回显 | 全局 try/catch + 日志面板 |
| 许可合规 | 不把 AGPL 的 ultralytics 分发进应用 | 仅文件级交换 ONNX，见开发清单第 7 章 |
| 可维护 | 主/渲染/preload/共享类型分层；关键纯函数有单测 | 15 个单测 |
| 隐私 | 全部数据本地处理，无任何外发请求 | 截图/模型/缓存均在 userData |

## 5. 明确不做（一期范围外）

- 非模拟类游戏的复杂操控（MOBA 摇杆、FPS 视角、连招宏）。
- 游戏协议抓包/内存读写/外挂式注入。
- 云端训练、账号体系、多端同步。
- 自动打码/绕过人机验证等违规能力。
- macOS/Linux 打包发布（代码可移植，本期只打 Windows 包配置）。

## 6. 验收用例（端到端）

1. 启动应用 → 打开 `seer://fixture/game-demo.html` → 探测：1 个画布、`contextType=2d`、自动选中。
2. 生成离线演示模型 → 单次检测：返回 12 条检测框，四套坐标齐全。
3. 点击检测结果（或走任务执行器）→ 夹具内 START 可进入 play、点击金币/怪物后 score/coins 增加。
4. 保存功能模块 → 刷新页面 → 页面签名匹配 → 模块自动恢复。
5. dryRun 循环任务：按标签匹配 → tick 计数增长 → 达 maxLoops 自动结束 → 不产生真实点击。
6. 标注 → 导出数据集目录 → `python train.py` → `python export.py` → 应用导入 ONNX → 识别生效。
