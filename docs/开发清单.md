## 4. YOLO26 推理平台从零搭建（分步指南）

目标：不写一行训练代码也能先跑通官方模型；随后用自己的截图训练游戏 UI 检测器，导出 ONNX 导回应用。

官方文档：<https://docs.ultralytics.com/zh/models/yolo26>

### 4.1 YOLO26 基本概念（先建立心智模型）

- YOLO26 是 Ultralytics 2025 年的检测系列，提供 n/s/m/l/x 五档，起步微调建议 **n 或 s**（CPU 推理可接受）。
- 输入 RGB，`imgsz` 默认 640（必须是 32 的倍数）；letterbox 填充灰色 114。
- 两种 ONNX 输出头（本应用都支持）：
  - **端到端头（推荐，`nms=False` 导出）**：输出 `(1, 300, 6)`，每行 `[x1,y1,x2,y2,score,classId]`，最多 300 个，**模型内置 NMS，应用侧直接解码**。
  - **标准头（默认导出）**：输出 `(1, 4+nc, 8400)`（转置后每行 8400 个候选），需要应用做置信度过滤 + per-class NMS，本应用已实现（[postprocess.ts](file:///C:/Code/Learn/SeerBrowserPro/src/main/vision/postprocess.ts)）。
- YOLO26 仍使用 ultralytics 包与 `YOLO('yolo26n.pt')` API，训练/验证/导出命令与 YOLO11 系列一致。

### 4.2 第一步：30 分钟跑通官方模型链路

```powershell
# 在工程根目录、已激活 venv 的终端
python python\fetch_official.py .\models-local\official
```

脚本做三件事（[fetch_official.py](file:///C:/Code/Learn/SeerBrowserPro/python/fetch_official.py)）：

1. `pip install -U ultralytics`；
2. 自动下载 `yolo26n.pt`（COCO 80 类预训练权重）；
3. `model.export(format='onnx', nms=False, opset=17, imgsz=640, simplify=True)`，
   产出 `models-local\official\yolo26n.onnx` + `classes.json`。

然后：启动应用 →「模型」面板 → 导入 `yolo26n.onnx`（同目录 classes.json 会被一并读取）→ 打开任意网页 →「检测」面板点单次检测。COCO 类没有人能识别游戏按钮，但能验证"截图→预处理→推理→框选→覆盖层"整条链路。

> 也可以不装任何东西：「模型」面板一键生成**离线演示模型**（应用调用 [make_dummy_model.py](file:///C:/Code/Learn/SeerBrowserPro/python/make_dummy_model.py)，仅依赖 `onnx` 包，产 12 个固定框），用于联调与自动化测试。

### 4.3 第二步：采集游戏画面

两种方式：

- **应用内标注面板**（推荐）：探测并选中游戏画布 → 标注工作区抓帧 → 在画面上拖框、选标签 → 保存。每保存一条，主进程导出一张 PNG 到 `userData/dataset/images/`，并在 `labels/` 写同名 YOLO 标注 txt（每行 `classId cx cy w h`，全部 0~1 归一化）。
- 外部截图也行：把 PNG 放进 `dataset/images/`，用 LabelImg / X-AnyLabeling 等工具按 YOLO 格式标注到 `dataset/labels/`。

建议量级（经验值，先求收敛再求精）：

- 首批 10~20 个高频标签（参考 [starter-classes.md](file:///C:/Code/Learn/SeerBrowserPro/python/starter-classes.md) 的 21 个起步标签）；
- 每类 50 张起步，按钮类小目标尽量 100+；
- 同一画面不同弹窗/不同分辨率各采一批；窗口拖成不同大小采集，提升跨分辨率泛化。

数据集目录（ultralytics 检测格式）：

```
dataset/
  images/   0001.png 0002.png ...
  labels/   0001.txt 0002.txt ...
  data.yaml
```

`data.yaml` 示例（应用导出时自动生成）：

```yaml
path: C:/Users/you/AppData/Roaming/seer-browser-pro/dataset
train: images/train
val: images/val
nc: 6
names: [start_button, close_button, confirm_button, resource_icon, upgrade_button, dialog]
```

应用导出的数据集默认平铺；正式训练前按 8:2 拆分到 `images/train`、`images/val`（标签同步）。可用任意脚本或手动移动。

### 4.4 第三步：标注规范（决定模型上限）

1. 标签按**功能**命名不按外观：统一 `close_button`，而不是 `red_x_v2`。
2. 只框"可操作 / 需要判断状态"的元素；装饰不标。
3. 框紧贴图形边界；遮挡超 70% 的样本不标。
4. 不点击的状态元素也值得标（如 `hp_bar`、`dialog`），供任务编排做条件判断。
5. 标签一旦用于训练不要改名；新增标签时同步更新 `data.yaml` 的 `nc/names` 顺序，类别顺序必须与应用里 classes.json 一致。

### 4.5 第四步：训练（从 yolo26n 微调）

```powershell
# 首次会再自动下载 yolo26n.pt 作为预训练权重
python python\train.py --data .\dataset\data.yaml --weights yolo26n.pt `
  --epochs 100 --imgsz 640 --batch 16 --device cpu --name seer_game_ui
```

参数说明（[train.py](file:///C:/Code/Learn/SeerBrowserPro/python/train.py)）：

- `--weights yolo26n.pt`：从 COCO 预训练权重迁移；有显卡用 `--device 0`（CUDA），速度差几十倍。
- `--batch`：数据少或显存小就降到 8/4。
- 结果在 `runs/detect/seer_game_ui/weights/best.pt`；`results.png` 看 loss/mAP 曲线。
- 小数据集经验：epochs 100 + patience 30 早停通常够；过拟合就补样本，别盲目加轮次。

### 4.6 第五步：验证

```powershell
# 标准头（带 NMS）
python python\val.py --weights runs\detect\seer_game_ui\weights\best.pt --data .\dataset\data.yaml
# 端到端头指标对比
python python\val.py --weights runs\detect\seer_game_ui\weights\best.pt --data .\dataset\data.yaml --no-nms
```

关注 `mAP50`（按钮检测看这个就够）与 `mAP50-95`（框贴合度）。某一类差就回去补该类样本（误检多补负样本/背景图，漏检多补该类正样本）。

### 4.7 第六步：导出 ONNX

```powershell
# 推荐：端到端头 (1,300,6)，应用免 NMS
python python\export.py --weights runs\detect\seer_game_ui\weights\best.pt --out .\models-local\custom

# 需要与其他推理框架对齐时：标准头 (1,4+nc,8400)
python python\export.py --weights runs\detect\seer_game_ui\weights\best.pt --out .\models-local\custom --standard
```

产物：`best_e2e.onnx`（或 `best_std.onnx`）+ 同目录 `classes.json`（类别名数组，顺序即 classId）。opset 17、已 simplify。

### 4.8 第七步：导回应用并验证

1. 应用「模型」面板 → 导入 ONNX（manifest 记录 inputSize=640、head=auto、conf/iou 阈值）。
2. 打开游戏页 → 单次检测 → 核对每个标签的框；阈值可在模型设置里调。
3. 把识别正确的框「存为功能模块」：缓存的是**归一化坐标 + 32×32 模板**，换窗口大小依然能点中。
4. 「任务」面板配置 loop（按标签循环点击）或 sequence（步骤序列），先开 **dryRun** 预演，确认匹配日志无误再实跑；Esc 随时急停。

### 4.9 第八步：迭代闭环（让模型越用越准）

```
误点/漏点 ─▶ 当场抓帧 ─▶ 标注面板修正框 ─▶ 累积进 dataset
     ▲                                      │
     └──── 导回应用 ←── 导出 ONNX ←── 重新 train/val
```

建议维护版本化模型名（`seer_ui_v1.onnx`、`v2.onnx`），manifest 保留旧模型，效果回退可一键切回。

## 5. 模型输出契约与后处理

- 引擎（[yolo-engine.ts](file:///C:/Code/Learn/SeerBrowserPro/src/main/vision/yolo-engine.ts)）读取 ONNX 的输入名/形状自动适配，输出按最后两维判定：
  - 末维为 6 → e2e：过滤 score≥conf，直接取坐标；
  - 维度形如 `(4+nc, N)` → standard：转置后取 4 个框坐标 + nc 类 logits，取 `softmax/argmax` 分类，conf 过滤，再做**按类 IoU NMS**（IoU 阈值可调，单测覆盖）。
- 坐标均为 letterbox 后 640 空间，先逆 letterbox 回到 bitmap。
- 预处理 100% 纯函数，见 [preprocess.ts](file:///C:/Code/Learn/SeerBrowserPro/src/main/vision/preprocess.ts)（灰边 114、NCHW、裁剪、缩略图均有单测）。

## 6. 统一坐标契约（全项目最重要的约定）

四套坐标定义在 [types.ts](file:///C:/Code/Learn/SeerBrowserPro/src/shared/types.ts)，换算集中在 [coords.ts](file:///C:/Code/Learn/SeerBrowserPro/src/main/vision/coords.ts)：

| 坐标系 | 含义 | 用途 |
|---|---|---|
| bitmap | 抓帧物理像素（含 DPR 缩放） | 模型输入/输出 |
| css | 浏览器视口 CSS 像素 | sendInputEvent 点击 |
| canvasNorm | 相对选中 Canvas 的 0~1 | **功能模块缓存**（跨分辨率） |
| viewportNorm | 相对整个视口的 0~1 | 无选中画布时的缓存兜底 |

链路：`模型框(640) → 逆 letterbox → bitmap → ÷DPR 并扣除画布视口偏移 → css → 归一化缓存`；点击前反向实时还原。DPR、letterbox、归一化往返、IoU、缓存框解析均有单测（[coords.test.ts](file:///C:/Code/Learn/SeerBrowserPro/tests/coords.test.ts)）。改动坐标逻辑必须先改/补单测。

## 7. 许可与进程隔离（AGPL 合规）

- Ultralytics 为 **AGPL-3.0**，本应用自身代码不与之混合分发：
  - Node/Electron 进程**只加载 ONNX 模型文件**（ONNX 是开放格式，模型权重许可以其自身来源为准）；
  - 所有 ultralytics 调用都在用户本机的独立 Python 进程中，由用户自行 pip 安装，应用仅通过命令行交换**文件**（PNG/YAML/PT/ONNX/JSON）；
  - 安装包不打包 ultralytics，`resources/python` 只放脚本文件。
- 应用内 npm 依赖（onnxruntime-node、Electron、React 等）均为 MIT/Apache-2.0 类许可。
- 项目源码以 MIT 发布；用户训练的模型权重归用户所有。

## 8. 关键调试经验（踩坑记录）

1. **preload 隔离世界改不到主世界原型**：`HTMLCanvasElement.prototype.getContext` 的包装必须进入主世界。最终方案是用主进程 CDP（`webContents.debugger`）`Page.addScriptToEvaluateOnNewDocument` 注入——同步早于页面脚本、无视 CSP、覆盖 iframe。注意 `Page.enable` 在全新未提交导航的 WebContents 上会挂起，要在首次 `did-start-loading` 后再发命令（见 [tab-manager.ts](file:///C:/Code/Learn/SeerBrowserPro/src/main/browser/tab-manager.ts)）。曾尝试 preload + appendChild（脚本异步执行会晚于小页面 body 脚本）与 document.write（自定义 scheme 双提交文档下会打断解析），均已废弃。
2. **Electron 启动即崩（-36861）**：GPU 进程问题，ready 前 `app.disableHardwareAcceleration()`。
3. **单实例锁 0x5**：开发态 userData 重定向到工程内 `.userdata/`。
4. **sendInputEvent 事件名**：`mouseMove / mouseDown / mouseUp`（不是过去式）；只有它产生的事件 `isTrusted=true`。
5. **TS 配置**：勿用 `baseUrl`+裸 `paths`，统一 `./src/...`；注入页面脚本含 DOM 类型，node 侧 tsconfig 需带 DOM lib。
6. **DPR≠1 时点击偏移**：一切点击坐标必须走 coords.ts，不要在业务代码里手算。
7. **CDP 端到端测试**：dev 加 `--remote-debugging-port=9222`，Node 24 自带 WebSocket/fetch 可直连；页面导航后注意执行上下文新旧并存，断言用轮询 + 页面内测试钩子（夹具暴露 `window.__seerGame`）。
